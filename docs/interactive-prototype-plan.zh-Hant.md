# 本地中文查核工作台：本輪開發計畫

本輪已授權製作本機 app、執行本機開發／瀏覽器測試，以及依核對結果接入模型 runtime／下載流程。這是本輪範圍，取代舊 prototype plan 對啟動服務的限制；不授權外網監聽、修改共用環境、操作受保護的外部專案資產或由實作者進行 Git 發布。Git 與最終公開由原目標對話處理。

## 先完成可操作的查核路徑

1. 沿用標準庫核心，以 `serve --review` 載入已存在且通過完整性檢查的 review。未指定檔案時，使用合法公開的合成語音與既有真實 GPU 候選結果。
2. 在工作台完成原音播放／選段、原稿與候選並排、逐字差異、工具 evidence／trace、人工採用／保留原稿／復原，以及 JSON／TXT／audit 下載。後續公開入口預設英文，提供可記住明確選擇的繁體中文介面；語言切換不改寫來源文字、候選、raw trace 或查核者輸入。
3. 每次決策以 exclusive-create 另存新修訂，不覆寫原 review、原始 ASR 或音訊。用 revision 檢查阻止舊畫面覆蓋新決策。
4. 先以既有結果完成可靠 UI，不將「顯示既有 GPU 結果」呈現成「正在執行模型」。背景執行查核與 LLM policy 待此路徑驗收後接續。

## 安全與資料邊界

- HTTP server 固定監聽 `127.0.0.1`，只接受符合實際 port 的 Host／Origin。變更必須附隨機 mutation token、JSON Content-Type 與大小受限內容。
- 路由採白名單，音訊只服務啟動時已驗證的單一 source；支援受限單一 byte range，不提供任意檔案或目錄存取。啟動時比對 source hash，播放前檢查檔案是否變更。
- 靜態前端不載入外部腳本、字型或追蹤資源。所有使用者文字以 `textContent`／DOM node 呈現；不把逐字稿當 HTML。
- 本機 review／下載可能含絕對 source locator，留在 `.local/`。公開示範保存 portable manifest，在啟動時才產生本機 locator，不發布私人路徑。
- 清楚顯示合成示例、手動植錯初稿、既有 GPU 候選與人工決策的區別。未標記不代表正確，工程通過不代表品質或省工效益。

## 視覺決策

- 使用 design-taste app run，`framed-sheet`，seed `618805924`。選它是因為這是長時間回聽與逐字比較的工具，淺框架與白色工作頁可把注意力留給原文與差異。
- 首屏問題：這一段的候選是否有足夠原音與工具證據，值得採用？最大區域是原稿／候選比較，最常用動作位於同區。
- 產品面貌：低彩度青灰框架、繁中本機字型、原稿與候選的相鄰文字。signature 是同一段落的原音位置、差異與可復原決策，不使用假波形或虛構指標。
- 色彩只用在新增／刪除文字與狀態；近黑主按鈕。dealt IBM Plex Sans 不含完整繁中且本地工作台不依賴外部字型，因此以本機 Microsoft JhengHei／系統 CJK 字型取代並記錄此調整。
- 桌面採 228px queue＋可縮放主工作區，主工作區以 24px 間距分欄；手機單欄、queue 可折疊，主要觸控目標至少 44px。

## 驗證與完成條件

沿用既有核心測試，新增實際 HTTP server 測試：任意檔案路徑拒絕、Host／Origin／token、body 上限、byte range、source 內容變更、人工採用／復原／修訂一致性，以及背景工作錯誤不覆蓋既有結果。以真實瀏覽器核對桌面／平板／手機、播放及下載；只在實測後更新公開 README 與截圖。工作台預設不啟動 GPU；有明確模型設定且按執行才載入，實機 GPU 驗證由目標對話核對資源後執行。不改共享環境。
